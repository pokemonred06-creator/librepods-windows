# Reverse Engineering Analysis of the AirPods Windows Driver (`MagicAAP.sys`)

## Executive Summary
Binary string analysis and import table inspection of `MagicAAP.sys` reveal that the driver is **not** custom proprietary firmware. Instead, it was compiled directly from Microsoft's official, open-source Windows Driver Kit (WDK) sample:

**[Microsoft Windows Driver Samples — Bluetooth Echo L2CAP Profile Driver (`bthecho`)](https://github.com/microsoft/Windows-driver-samples/tree/main/bluetooth/bthecho)**

Specifically, it is a compilation of Microsoft's **`bthecho/bthcli`** (Bluetooth L2CAP Client) sample with minor configuration changes (custom Device Interface GUID and Hardware ID matching Apple AirPods).

---

## 1. Binary Evidence & Forensic Analysis

### A. PDB Debug Path
Extracted string from the binary:
```
C:\Users\steam\Local Storage\Repos\steam3d\MagicAAP\MagicAAP\x64\Release\MagicAAP.pdb
```

### B. WDK Sample Context Structures
The compiled binary contains the exact context structures from Microsoft's `bthecho/bthcli`:
```
BTHECHO_CONNECTION
BTHECHOSAMPLE_CLIENT_CONTEXT
BTHECHOSAMPLE_CLIENT_FILE_CONTEXT
```
These structures correspond directly to:
- `bthecho/bthcli/sys/device.h`
- `bthecho/bthcli/sys/device.c`
- `bthecho/bthcli/sys/queue.c`

### C. Digital Signature & Certificates
Extracted signing certificate metadata:
```
$WDKTestCert steam,1335827946974396300
```
This is a standard self-signed test certificate generated by Visual Studio / WDK during a test build (`$WDKTestCert`). This explains why Windows requires **Test Mode** (`bcdedit /set testsigning on`) to load the driver.

### D. Imports & Dependencies
The driver imports only two system libraries:
1. `ntoskrnl.exe` (Event management: `KeInitializeEvent`, `KeWaitForSingleObject`, `KeSetEvent`, `IoWMIRegistrationControl`)
2. `WDFLDR.SYS` (KMDF Version 1.15 binding: `WdfVersionBind`, `WdfLdrQueryInterface`)

## 2. Architecture: How the Driver Works

```
+-------------------------------------------------------------+
|              LibrePods (User-Space Application)            |
|       CreateFileW("\\\\?\\BTHENUM#{74ec2172...}")          |
|       WriteFile() [Sends AAP packet]                        |
|       ReadFile()  [Receives AAP telemetry/battery]          |
+-------------------------------------------------------------+
                              |
                              v (Win32 I/O subsystem)
+-------------------------------------------------------------+
|              MagicAAP.sys (KMDF 1.15 Client Driver)         |
|                                                             |
|   1. EvtDriverDeviceAdd:                                    |
|      - Registers GUID_DEVINTERFACE_MAGICAAP                 |
|      - Matches Hardware ID BTHENUM\{74ec2172...}            |
|                                                             |
|   2. Queue Dispatcher (queue.c):                            |
|      - EvtIoWrite -> Submits BRB_L2CA_ACL_TRANSFER (Tx)     |
|      - EvtIoRead  -> Submits BRB_L2CA_ACL_TRANSFER (Rx)     |
+-------------------------------------------------------------+
                              |
                              v (IOCTL_INTERNAL_BTH_SUBMIT_BRB)
+-------------------------------------------------------------+
|               Windows Native Bluetooth Stack                |
|                    bthport.sys / bthsubsys                  |
+-------------------------------------------------------------+
                              |
                              v (Over-the-Air L2CAP Channel)
+-------------------------------------------------------------+
|               Apple AirPods Pro (H1 / H2 Chip)             |
|                  AAP L2CAP Service Endpoint                 |
+-------------------------------------------------------------+
```

### Key Takeaway
`MagicAAP.sys` contains **zero proprietary Apple protocols, zero decoding algorithms, and zero custom audio processing**. It functions entirely as a **raw L2CAP pipe bridge** that allows user-space applications (like LibrePods) to send and receive raw Bluetooth packets directly to and from the AirPods.

## 3. How to Build an Open-Source, Clean-Room Replacement (`LibreAAP.sys`)

Because the entire driver source is public under the MIT license in Microsoft's official repository, you can compile your own version without relying on third-party pre-compiled binaries:

1. **Clone the Microsoft Sample**:
   ```bash
   git clone https://github.com/microsoft/Windows-driver-samples.git
   cd Windows-driver-samples/bluetooth/bthecho/bthcli
   ```

2. **Configure the Hardware ID & GUID**:
   - In `bthecho.inf`: Set Hardware ID to `BTHENUM\{74ec2172-0bad-4d01-8f77-997b2be0722a}`.
   - In `device.h`: Define `GUID_DEVINTERFACE_MAGICAAP` (`{74ec2172-0bad-4d01-8f77-997b2be0722a}`).

3. **Compile with Visual Studio + WDK**:
   - Open `bthcli.vcxproj` in Visual Studio 2022.
   - Build for `Release x64`.
   - The resulting `.sys` file is your fully open-source, auditable `LibreAAP.sys`.

4. **Signing Options**:
   - **For Personal Use**: Self-sign with a custom certificate using `signtool.exe` (run in Windows Test Mode).
   - **For Production Distribution**: Submit the driver package to the **Microsoft Hardware Developer Center (WHQL)** for attestation signing, allowing it to run on standard retail Windows without Test Mode enabled.
